## 1. The rubric

Three dimensions, each scored 0, 1 or 2 against one thing, null where it does not apply. The full definitions and the pass/fail examples are in [`eval/rubric.yaml`](../eval/rubric.yaml); the grader reads the definitions as written (not the examples), with the passages under the headings the model saw, the question, the reference answer and the marked answer.

- **groundedness**: Is every claim in the ANSWER stated in the PASSAGES? Reads the answer sentence by sentence against the passages only, never against what you know of the software. Applies when the answer is an answer, not the abstention sentence (null otherwise).
- **completeness**: Does the ANSWER carry the main points of the REFERENCE ANSWER? Reads the answer against the reference answer, main point by main point; extra correct detail is fine. Applies when the reference answer is an answer, not the abstention sentence (null otherwise).
- **abstention**: Did the ANSWER make the right call about what the PASSAGES cover? Reads whether the passages answer the question, in whole, in part or not at all, and whether the answer says so. Applies when always.

A grade is also read as pass or fail at the operating threshold (`operating` in the rubric): groundedness passes at ≥ 1, completeness passes at ≥ 1, abstention passes at ≥ 2. The overall verdict passes when every applicable dimension passes.

### `mh-undo-after-history-zero` · multi-hop · expected to answer

**Q:** I set revisionHistoryLimit to 0 on my Deployment. Can I still run kubectl rollout undo?

**A:** No, a Deployment with `.spec.revisionHistoryLimit` set to 0 cannot be rolled back.[1]
> Setting the field to zero removes every old ReplicaSet that has 0 replicas, so you can't undo a new rollout.[2]
> This happens because each revision's configuration is stored in its ReplicaSet, so deleting that ReplicaSet removes the ability to roll back to that revision.[2]
> The cleanup only starts after the Deployment reaches a complete state.[1]
