## 1. The sampling policy

A window is 7 days of live traces. Every rule that fires is recorded on the sample; `random` keeps a stable 10% of the traces no rule picked, so the window stays representative; at most 100 samples a window.

| Rule | Fires when | Why |
|---|---|---|
| `dissatisfied` | a person marked the answer not helpful (`POST /feedback`) | a person marked the answer not helpful (POST /feedback); the strongest signal and the rarest |
| `uncited` | answered with under 80% of the claims cited | the answer left over a fifth of its claims uncited, the floor the offline verdict reads |
| `low-confidence` | answered with the best passage's cosine under 0.60 | answered, with the best passage under the cosine floor the dataset calls a near miss |
| `no-answer` | the abstention sentence (no passage qualified, or the model abstained) | the abstention sentence; either the corpus does not cover it or a false abstention |
| `long-context` | the passages at or over 90% of the token budget, or some left out | the passages filled the token budget or some were left out; where overload shows |
| `long-query` | over 25 words | over 25 words; the multi-part and the rambling questions the benchmark has few of |
| `identifier` | a camelCase, dotted, snake_case or `--flag` token in the question | a camelCase, dotted, snake_case or --flag token; the questions keyword search wins |
| `error` | the model call failed | the model call failed |
| `random` | a stable 10% of the rest | a stable 10% of the rest, so the sample is not only the suspicious traffic |

## 4. Reading the report

The offline gates say whether a change broke what the dataset measures; this report says what the traffic asks that the dataset does not. A cluster that recurs across windows is a record to add (`online promote`), a floor to move, or a source to ingest. A `dissatisfied` sample outranks everything else: it is the one signal that comes from the person the answer was for. Adding harvested records moves the dataset version, so the baseline is run again and the freeze renewed; that is the loop closing, not a side effect.

```sh
uv run infra-docs-rag serve                                   # the service; POST /answer, POST /feedback
uv run infra-docs-rag online sample [--until YYYY-MM-DD]      # the window's samples → eval/online/<window>.json
uv run infra-docs-rag online judge                            # jev reads the answered samples
uv run infra-docs-rag online report                           # this report
uv run infra-docs-rag online promote --n 10                   # draft records from the failed samples → eval/dataset/harvested.yaml
uv run infra-docs-rag online promote --merge                  # append them to records.yaml, then rerun the baseline and freeze
```
