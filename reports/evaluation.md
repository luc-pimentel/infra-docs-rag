### `lock-config` · paraphrase · expected to answer

**Q:** Can I lock my app settings so nobody can change them after they are created?

**Baseline** (held): Yes, if your app settings are stored in a ConfigMap: Kubernetes lets you mark individual Secrets and ConfigMaps as immutable.[1]
> To do this, set the `immutable` field to `true`.[1]
> After that, you can't undo the setting or change the `data` or `binaryData` fields.[1]
> To change the settings later, you have to delete the ConfigMap and recreate it.[1]
> Existing Pods keep a mount point to the deleted ConfigMap, so it's recommended to recreate those Pods too.[1]
> The passages don't cover locking app settings that are stored anywhere other than a ConfigMap or Secret, such as Argo CD Application definitions.

Passages: [1] `k8s-configmap › ConfigMaps › Immutable ConfigMaps` ✓; [2] `k8s-pods › Pods › Pod security settings`; [3] `k8s-deployment-md › Deployments › Clean up Policy`; [4] `cncf-security-whitepaper › CLOUD NATIVE SECURITY WHITEPAPER › Cloud Native Layers › Security Policies, page 21`; [5] `argocd-declarative-setup-md › Declarative Setup › Applications › App of Apps`

### `configmap-live-update` · paraphrase · expected to answer

**Q:** If I edit a ConfigMap, do the files already mounted in my running pod change?

**Baseline** (held): Yes, the mounted files change, but not instantly.
> When a ConfigMap currently consumed in a volume is updated, projected keys are eventually updated as well.[3]
> The kubelet checks on every periodic sync whether the mounted ConfigMap is fresh, but it reads the current value from its local cache.[3]
> The delay can be as long as the kubelet sync period plus the cache propagation delay.[3]
> You set the cache type with the `configMapAndSecretChangeDetectionStrategy` field in the KubeletConfiguration struct.[3]
> Values you consume as environment variables don't update this way, and you need to restart the pod to pick them up.[3]

Passages: [1] `k8s-configmap › ConfigMaps › Using ConfigMaps › Using ConfigMaps as files from a Pod`; [2] `k8s-configmap › ConfigMaps › Using ConfigMaps`; [3] `k8s-configmap › ConfigMaps › Using ConfigMaps › Using ConfigMaps as files from a Pod › Mounted ConfigMaps are updated automatically` ✓; [4] `k8s-configmap › ConfigMaps › ConfigMaps and Pods`; [5] `k8s-configmap › ConfigMaps`

**Candidate** (partly uncited): Yes, the mounted files change on their own, but not right away.[1]
> The kubelet checks on every periodic sync whether the mounted ConfigMap is fresh, but it reads the value from its local cache.
> You set the cache type with the `configMapAndSecretChangeDetectionStrategy` field in the KubeletConfiguration struct.
> The total delay can be as long as the kubelet sync period plus the cache propagation delay.
> ConfigMap values used as environment variables do not update, so the pod has to be restarted.[1]
> If the ConfigMap is marked `immutable: true`, you can't edit its `data` at all, so you can only delete it and create it again.

Passages: [1] `k8s-configmap › ConfigMaps › Using ConfigMaps › Using ConfigMaps as files from a Pod › Mounted ConfigMaps are updated automatically` ✓; [2] `argocd-declarative-setup-md › Declarative Setup › Repositories › Repositories using self-signed TLS certificates (or are signed by custom CA)`; [3] `k8s-configmap › ConfigMaps › Using ConfigMaps › Using ConfigMaps as files from a Pod`; [4] `k8s-configmap › ConfigMaps › Using ConfigMaps`; [5] `k8s-configmap › ConfigMaps › Immutable ConfigMaps`

## 4. Reading the report

A gate compares one metric: `no-drop` and `no-rise` against the baseline with the tolerance the gate names, `min` and `max` against a fixed value. A critical gate that fails blocks (the command exits 1); the others warn. Retrieval metrics count the labelled in-scope questions, grounding metrics the answered ones among them, abstention the out-of-scope and adversarial sets. Costs are at API list prices for the tokens the run used, whatever it was billed to; latency is retrieval plus the model's time, on the machine named above.
