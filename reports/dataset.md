## 1. The schema

| Field | What it holds |
|---|---|
| `id` | unique across the curated and generated records |
| `query` | the question as a person would type it |
| `category` | fact-lookup, multi-hop, ambiguous, no-answer, stale, adversarial |
| `expect` | what a right reply does: `answer`, `abstain` (the fixed sentence), `partial` (answer what the passages cover, name the rest), `clarify` (name the readings, ask which) |
| `difficulty` | easy (shares the passage's words), medium (paraphrase, or two passages), hard (a condition, an exception, a deprecation, an ambiguity) |
| `failure_mode` | the failure this example is in the set to catch; `none` for a clean example |
| `split` | `dev` (read while the scoring rules were revised; tune on these) or `test` (held out) |
| `origin` | `benchmark` (a question from eval/*.yaml), `traces` (asked of the running service), `hand-written`, `generated` (a model wrote it, the audit kept it) |
| `source_doc_ids` | the sources the contexts come from |
| `contexts` | chunk ids of the passages a right answer rests on, under the chunking named at the top of the file; empty for an abstention |
| `reference_answer` | what a right answer says, from the contexts alone |
| `tags`, `benchmark_id`, `note` | free tags; the benchmark question the record came from; why it is in the set |

Failure modes:

| Mode | Meaning | Measured by a run? |
|---|---|---|
| `none` | a clean example: the run should answer it from the passages, and did | not yet |
| `false-abstention` | an in-scope question that got the abstention sentence | yes |
| `retrieval-miss` | no right passage among the ones the model read | yes |
| `wrong-passage` | the answer cites a passage that is not a right one | yes |
| `uncited-claims` | under 80% of the answer's claims carry a verified citation | yes |
| `unverified-citation` | a typed citation that did not check out against its passage | yes |
| `answered-anyway` | a question that should get the abstention sentence, answered from memory or a near miss | yes |
| `judge-misread` | the judge reads a grounded answer as ungrounded or fabricated | yes |
| `fabrication` | the answer states a fact no passage gives, or accepts a false premise | not yet |
| `stale-answer` | the answer presents a deprecated field, flag or method as current | not yet |
| `wrong-reading` | an ambiguous question answered under one reading without naming the others | not yet |
| `missing-hop` | a question whose answer spans two passages, answered from one | not yet |

## 6. Running it

```sh
uv run infra-docs-rag dataset check                       # schema, chunk ids, sources, benchmark labels; exit 1 on a problem
uv run infra-docs-rag dataset generate --n 30 --seed 13   # sample chunks, write eval/dataset/generated.yaml through claude -p
uv run infra-docs-rag dataset report                      # check, then write reports/dataset.md and eval/dataset/schema.json
```

A new curated record is an entry in `records.yaml` with its contexts named by chunk id (`search` prints them) and its reference answer written from those passages alone. A regenerated testset needs a new audit: the decisions are per example id, and `check` refuses an audit that misses one.
