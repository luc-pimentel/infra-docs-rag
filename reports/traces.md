## 1. The trace schema

Every answer writes one trace: the question, the pipeline version and its lineage, every stage's time, what the first stage ranked with its scores, what the reranker made of every candidate, what the pack step kept and what it dropped and why, what the model wrote and cited, what the judge and the reader read. Since stage 17 it carries the identifiers that link it to the eval example and the experiment:

| Tag | What it holds |
|---|---|
| `example_id` | the record (or benchmark question) the answer is for |
| `run` | the saved run under `eval/runs/` the trace belongs to |
| `dataset_version` | `<records>+<hash>` of the dataset the run answered (section 9 of the spec) |
| `version` | the pipeline version, from `eval/versions.yaml` |
| `prompt_version` | `<name>+<hash of the wording>` |
| `model_version` | the generator's model id |
| `retriever_version` | `<version>+<hash of the retrieval configuration>` |
| `index_version` | the hash of the index read |

and reads as spans, in request order, each with its time and the attributes a diagnosis needs:

| Span | Covers | Attributes |
|---|---|---|
| `retrieve` | embed → dense + lexical → fuse → rerank → pack | candidates, first-stage and reranked depth, packed, dropped under the floor and past the budget, top score, what degraded |
| `prompt` | the passages under their headings, the system prompt | passages, tokens, budget, prompt version |
| `generate` | the model call | model, tokens in and out, cost, outcome, error |
| `verify` | every typed citation checked against its passage | citations, cited chunks, cited share, claim share, uncited segments |
| `judge` | jev on the answer against the passages | grounded, fabricated, gap named |
| `read` | jev on the answer against the reference | relevant, agrees with the reference, deprecation named, readings named |

`trace_answer(...)` in `observe/trace.py` writes it; `Trace.tags` and `Trace.spans` read it back; the run keeps `trace_id` on each case, so a row in a report opens onto its trace.

## 5. The process

1. `dataset compare` names the records that stopped holding and links each to its trace in both runs. 2. `dataset diagnose` reads the trace and names the span: for a record that names its passages, whether they ranked, where the reranker put them, whether the pack step dropped them and why; for one that reached the model, whether the prompt held, whether the context was at its budget, else generation. 3. The cause decides the fix: a first-stage miss is a chunking or embedding question, a rerank miss a depth or model question, a budget drop a packing question, a prompt failure a wording question, and a generation failure a model or effort question. 4. The fix is a pipeline version; the regression test measures it; the trace of the fixed record shows the span that moved.

```sh
uv run infra-docs-rag dataset run --generator claude-code --version <name>   # writes eval/runs/<run>/traces.jsonl beside the run
uv run infra-docs-rag dataset diagnose --run dataset-v3-budget-claude-code-84 --run dataset-v4-rerank-50-claude-code-84   # this report
uv run infra-docs-rag traces --id <trace_id>                                  # one trace in full, from the log
uv run python scripts/backfill_traces.py eval/runs/<run>                     # traces for a run made before stage 17: the saved answer, the retrieval replayed
```
